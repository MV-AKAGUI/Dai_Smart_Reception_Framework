# 🏛️ VIBE CODING DAISUGI — PROTOCOLO DE GOVERNANÇA PERMANENTE

## Trigger
always_on

## Description
Aplica obrigatoriamente as diretrizes da Arquitetura de Vibe Coding Daisugi e a Homeostase do Dr. Taylor Code em todas as conversas, decisões, novos módulos e auditorias em qualquer aplicação do ecossistema DAISUGI dentro do Antigravity IDE.

---

## Mandamentos Inegociáveis do Vibe Coding Daisugi

### 1. Condução Arquitetural pelo Dr. Taylor Code & Conselho Clínico
- Toda concepção de arquitetura, novo módulo ou refatoração no ecossistema é avaliada sob a ótica de **Homeostase Computacional** do Dr. Taylor Code: latência submétrica, tolerância a falhas, concorrência assíncrona desacoplada O(1) e estabilidade de ambiente.
- Convocação multidisciplinar dos especialistas:
  * **Dr. Taylor / Qwen 2.5 Coder:** Homeostase de software, código, matemática e robustez de APIs.
  * **Dr. SaulLM:** Compliance jurídico, contratos, catálogo de cadeiras e segregação de funções (SoD).
  * **Mistral-Nemo:** Tratamento de ambiguidade, sanitização semântica e casamento difuso (RapidFuzz).
  * **DeepSeek-R1:** Raciocínio formal estruturado, auditoria de hashes SHA-256 e custódia documental (HDW).

### 2. Zero Vazamento Cognitivo na Interface do Usuário (Identidade Soberana)
- O usuário corporativo (colaborador, diretor, engenheiro, fornecedor) **NUNCA deve escolher ou ver o modelo de IA na tela** (ex: caixas de seleção com Llama, Qwen, DeepSeek ou toggles técnicos).
- Quem atende o usuário é a identidade oficial da aplicação (ex: **DAI** na Portaria/Lobby).
- As LLMs operam 100% no back-end como órgãos internos do sistema nervoso, orquestradas invisivelmente por roteamento semântico.

### 3. RapidFuzz Grounding & Trava Anti-Alucinação Nível Zero
- Proibição terminante de inferências soltas ou alucinação de dados/nomes.
- Toda consulta e triagem de cotas, empreendimentos (WBS), normas e colaboradores passa por saneamento fonético/lexical com **RapidFuzz** e casamento vetorial fundamentado (RAG / Docling / HDW).
- Se a informação não constar com hash verificado no acervo fiduciário, o sistema acolhe educadamente declarando a ausência do registro.

### 4. Blindagem de Acesso, SoD e Contrato PAM/IGA (`Daisugi_Ecosystem_Cofre-PAM-IGA`)
- Toda autorização obedece à hierarquia do Cofre PAM:
  `Cadeira Nominal (Pessoa Física / RG)` ──► `Cadeira Funcional (Cargo / Alçada)` ──► `Token JWT Assinado O(1)`.
- **Regra de Ouro Inegociável SoD:** Quem cria a demanda (Maker) **NUNCA** pode aprovar a quarentena correspondente (Checker). Auto-aprovação é bloqueada com HTTP 403.
- Nenhuma credencial ou chave privada trafega desprotegida ou é exposta em repositórios.

### 5. Soberania Local & Otimização de Tokens no Antigravity IDE
- O Antigravity IDE atua como o Maestro Estratégico de Vibe Coding.
- Tarefas pesadas de inferência, PRDs do MetaGPT e auditorias periódicas devem priorizar o acervo de LLMs locais do desktop via Ollama (`http://127.0.0.1:11434`), garantindo **custo zero de tokens de nuvem/IDE** e autonomia offline.

### 6. Disciplina Karpathy (Surgical Patch, Verify and Stop)
- Intervenções de código devem ser cirúrgicas, na menor camada responsável, preservando código e comentários pré-existentes.
- Toda entrega requer prova executável de não-regressão antes de ser declarada concluída.
- Aplicação estrita da regra global de sincronização contínua com o GitHub (`git status` ──► `git pull` ──► `git add` ──► `git commit` ──► `git push origin main`).
